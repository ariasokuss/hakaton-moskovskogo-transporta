# Замеры производительности

**Условия.** Контейнер бэкенда ограничен **2 vCPU / 2 ГБ RAM** (`docker-compose.yml`),
как в нефункциональных требованиях ТЗ. Нагрузочный клиент — [hey](https://github.com/rakyll/hey)
(образ `williamyeh/hey`), запущен в той же docker-сети. 50 параллельных соединений,
20 секунд на эндпоинт, клиент принимает gzip.

Стенд: Docker Desktop на Windows-ноутбуке; нагрузочный клиент делит с сервисом
одну виртуальную машину Docker, то есть цифры **занижены** относительно
выделенного сервера.

## Результаты (26.09.2026)

| Эндпоинт | RPS | Среднее | p95 | p99 | Ошибки |
|---|---:|---:|---:|---:|---:|
| `GET /api/dashboard?date=…` — главный экран целиком | **551** | 91 мс | **179 мс** | 220 мс | 0 |
| `GET /api/forecast?route=17&horizon=month` — месяц по дням | **641** | 78 мс | **116 мс** | 186 мс | 0 |
| `GET /api/attention?date=…` — зоны внимания | **1 760** | 28 мс | **81 мс** | 95 мс | 0 |

RAM под нагрузкой: 0.77–1.6 ГБ из 2 ГБ, без swap. JVM: ZGC, `MaxRAMPercentage=75`.

## Что дало производительность

1. **Прогноз не в горячем пути.** Модель считается заранее; запрос читает
   неизменяемый снимок из памяти, в БД не ходит.
2. **Мемоизация главного экрана.** Снимок неизменяем → ответ при тех же параметрах
   тот же. Кэш привязан к снимку и сбрасывается сам при новом прогоне.
3. **Кэш готовых байтов.** Главный экран — 24 КБ JSON (3.7 КБ в gzip). Сериализация
   и сжатие на каждый запрос давали **243 RPS / p95 304 мс** — за пределом ТЗ.
   После кэширования готового gzip-ответа — **551 RPS / p95 179 мс**.

Сырые выводы — `first-run.txt`, `dashboard-cached.txt`, `dashboard-bytes-cached.txt`.

## Воспроизвести

```bash
docker compose up -d
NET=$(docker inspect -f '{{range $k,$v := .NetworkSettings.Networks}}{{$k}}{{end}}' tram-backend)
docker run --rm --network $NET williamyeh/hey -z 20s -c 50 "http://backend:8080/api/dashboard?date=2025-11-08"
```

## Горизонтальное масштабирование

Инстансы stateless: каждый держит свой снимок в памяти и раз в 30 секунд проверяет
в БД, не появился ли новый прогон. Состояния, привязанного к клиенту, нет —
инстансы взаимозаменяемы за любым балансировщиком.
