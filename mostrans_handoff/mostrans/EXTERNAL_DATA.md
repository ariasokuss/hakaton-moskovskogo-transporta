# Внешние источники данных (критерий 2а)

> **Принцип:** внешние данные используются **только как корректирующие коэффициенты (поправки)** к базовой модели.
> Базовый прогноз `boardings(route, date, hour)` строится **исключительно на основном датасете** (`train.csv` + `test.csv` / `labels/*`), как требует README датасета.
> Никакие значения пассажиропотока из внешних источников в модель не попадают.

```
ŷ(route, date, hour) = Base(route, date, hour)            ← модель на основном датасете
                     × K_calendar(route, day_type, hour)   ← источник 1: производственный календарь РФ
                     × K_school(date)                      ← источник 1b: школьные каникулы Москвы
                     × K_weather(date, hour)               ← источник 2: погода Open-Meteo
                     × K_event(route, date)                ← источник 3: события/работы на путях (Telegram Дептранса)
                     × K_traffic(score, hour)              ← источник 4: баллы пробок ЦОДД / Яндекс
                     × K_user                              ← ручные коэффициенты в UI (трафик/событие/сезон)
```

Все K хранятся отдельно от базовой модели, поэтому их можно менять в UI с немедленным пересчётом (это ещё +1 балл по критерию 2в).

Воспроизведение: `python external_data/build_external.py --download` (календарь, погода) и `python external_data/parse_deptrans_tg.py all` (события) + `python external_data/parse_deptrans_tg.py crawl --channel DtOperativno` и `extract --channel DtOperativno` (трафик), затем `measure`. Отчёты: `effects_report.csv`, `effects_tg_report.csv`.

| Обычный будний (контроль) | 127 | 1.01 |

**Ablation (дневной WAPE-score, коэффициент оценён leave-one-out по дням):**
**0.9047 → 0.9259 (+2.1 п.п.)** с календарной поправкой.

| Точка | центр Москвы 55.7558, 37.6173; почасово, Europe/Moscow, 01.01–31.12.2025 |
| Файлы | `external_data/weather_fact_hourly_2025.csv`, `weather_fcst_hourly_2025.csv` (сырьё — `*.json`) |
| Поля | `temperature_2m, apparent_temperature, precipitation, rain, snowfall, snow_depth, cloud_cover, wind_speed_10m, weather_code` |

**Какой файл для чего:**
- обучение коэффициента (янв–окт) — `weather_fact`;
- поправка на ноябрь–декабрь в сабмите — **`weather_fcst`** (архив прогнозов: то, что было известно заранее, без заглядывания в будущее). В проде сюда подставляется оперативный прогноз Open-Meteo.

**Измеренный эффект** (будни без праздников и каникул, n=127, OLS `log(объём/база) ~ temp + precip + snow`, коэффициенты на 1 std):

| Признак | fact | fcst |
|---|---:|---:|
| Температура | **+1.3%** | +1.2% |
| Осадки | **−1.0%** | −0.7% |
| Снегопад | +0.6% | +0.4% |

Мороз < −10 °C: 0.97 (n=3). Эффект небольшой, но устойчивый по знаку в обоих вариантах данных. Для ноября–декабря (холоднее, чем в обучающем окне сентябрь–октябрь) поправка по температуре даёт порядка −1…−3% к уровню.

## Источник 3. События, перекрытия, изменения трамвайной сети — Telegram Дептранса Москвы

| | |
|---|---|
| Ссылка | https://t.me/s/DtRoad — официальный канал Департамента транспорта Москвы (публичная веб-версия, без авторизации) |
| Способ получения | парсер `external_data/parse_deptrans_tg.py` (код в репозитории; инструкция ниже) |
| Сырьё | `external_data/deptrans_posts_raw.jsonl` — 4 646 постов за 01.01–31.12.2025 (`id, datetime_utc, text, url`) |
| Готовые файлы | `external_data/events_2025.csv` — 634 события; `external_data/effects_tg_report.csv` — замеры |
| Поля `events_2025.csv` | `post_id, post_date, post_hour, categories, tram_related, target_routes, event_dates, url, text` |
| Категории | `closure` (перекрытия), `tram_works` (ремонт/работы на путях), `tram_route_change`, `mass_event` (забеги, парады, концерты), `weather_alert`, `new_line` |

### Как работать с парсером

```bash
# из корня проекта; зависимости: python>=3.10, pandas, numpy (сеть нужна только для crawl)
python external_data/parse_deptrans_tg.py crawl     # скачать посты -> deptrans_posts_raw.jsonl (докачка: повторный запуск продолжает)
python external_data/parse_deptrans_tg.py extract   # посты -> events_2025.csv, traffic_scores_2025.csv
python external_data/parse_deptrans_tg.py measure   # замер эффекта на labels из dataset.zip -> effects_tg_report.csv
python external_data/parse_deptrans_tg.py all       # всё подряд (~10–15 мин)

# параметры
--channel DtRoad            # другой публичный канал, например mosgortrans
--start 2025-01-01 --end 2025-12-31
--sleep 0.7                 # пауза между запросами (не ставить меньше: канал ограничивает частоту)
```

Как устроен:
1. `crawl` — бинарным поиском находит `post_id` на дату `--end` и листает `https://t.me/s/<channel>?before=<id>` назад до `--start`. Каждая страница — около 20 постов; при сетевой ошибке делает паузу и повторяет запрос.
2. `extract` — регулярками размечает категории, номера **целевых** маршрутов (`№ 7`, «маршрутах 7 и 50», «17-й трамвай») и даты, упомянутые в тексте (`с 12 по 14 июля` → 3 даты). Словари категорий лежат в `CATEGORIES` в начале файла, их легко расширить.
3. `measure` — сравнивает объём в дни событий с медианой того же дня недели за ±4 недели и считает WAPE с поправкой и без неё (коэффициент оценивается leave-one-out).

**Для прогноза на ноябрь–декабрь берём только посты, опубликованные до 01.11.2025**, то есть то, что было известно на момент прогноза. Более поздние посты используются только для разбора ошибок и в описании.

### Измеренный эффект

| Фактор | n | Эффект |
|---|---:|---|
| Дни общегородских перекрытий (будни) | 35 | 1.020 против 1.007 в контроле — на трамвай **не влияет** |
| Массовые мероприятия (будни) | 64 | 1.015 против 1.006 — **не влияет** |
| Посты с упоминанием нашего маршрута (маршрут × день) | 20 | **0.929** от базы |
| **Кейс: закрытие участка Красносельская — Белорусский вокзал** (маршруты 7 и 50) | 1 эпизод | Пост [ограничение движения, 13.07](https://t.me/DtRoad/49910) и пост [восстановление, 13.08](https://t.me/DtRoad/50941). На этом интервале у **маршрута 7 объём −37%** (июнь 642k → июль 403k посадок), а у маршрута 50 рост +31% (527k → 690k, перераспределение пассажиров). Разрыв уровня в данных точно совпадает с датами из постов |

Выводы для модели:
- **Общегородские события → K=1** (эффект измерен и равен нулю, это тоже результат);
- **Работы на путях конкретного маршрута** → режимный коэффициент на интервал работ плюс исключение этого интервала из обучения уровня. Именно так размечаются аномалии маршрутов 7 и 50 летом.

## Источник 4. Дорожный трафик — баллы загруженности ЦОДД / Яндекс Пробки

Архива баллов пробок по API нет, поэтому источник собран из двух частей: **история** из оперативного канала Дептранса (там ЦОДД публикует баллы) и **онлайн-поток** из публичного XML Яндекса.

### 4a. История 2025 — Telegram «Дептранс. Оперативно»

| | |
|---|---|
| Ссылка | https://t.me/s/DtOperativno — оперативный канал Департамента транспорта (посты вида «По данным ЦОДД, вечером на дорогах — до 7 баллов», «ситуация оценивается в 5 баллов») |
| Способ получения | тот же парсер: `python external_data/parse_deptrans_tg.py crawl --channel DtOperativno` → `extract --channel DtOperativno` |
| Сырьё | `external_data/DtOperativno_posts_raw.jsonl` — 4 456 постов за 2025 год |
| Готовый файл | `external_data/DtOperativno_traffic_scores_2025.csv` — 344 значения балла за **150 дней** 2025 года (110 дней в янв–окт); плюс `traffic_scores_2025.csv` из @DtRoad |
| Поля | `post_id, date, hour, score (0–10), kind (fact/forecast), part_of_day (morning/evening), url` |

### 4b. Онлайн-поток — Яндекс Пробки

| | |
|---|---|
| Ссылка | https://export.yandex.ru/bar/reginfo.xml?region=213 — публичный XML, без ключа: текущий балл 0–10 по Москве, подсказка, тренд |
| Сборщик | `external_data/yandex_traffic_collector.py` → `yandex_traffic_live.csv` |
| Запуск | `python external_data/yandex_traffic_collector.py once` — один замер; `loop --every 600` — каждые 10 минут; в Docker — sidecar или cron `*/10 * * * *` |
| Роль | онлайн-признак для поправки `K_traffic` в сервисе (приём потоковых данных из нефункциональных требований) и накопление ряда вперёд |

### Измеренный эффект (янв–окт 2025, рабочие дни; `effects_tg_report.csv`)

| Замер | n | Результат |
|---|---:|---|
| Суточный максимум балла vs посадки за сутки | 58 дней | corr = **−0.03**, эффекта нет |
| **Посадки за 3 часа после поста с баллом** vs медиана тех же часов ±4 недели | 175 | corr = +0.08 |
| То же, **вечер (≥15 ч)** | 96 | corr = **+0.16** |
| Балл 0–4 (свободные дороги) | 75 | медиана **0.982** от базы |
| Балл 5 | 32 | 0.992 |
| Балл 6–7 (плотный трафик) | 66 | 0.998 |
| Ablation, суточная поправка `K_traffic` по корзинам баллов (LOO) | 58 дней | WAPE-score 0.9699 → **0.9709** (+0.1 п.п.) |

**Интерпретация:** эффект небольшой, но направление объяснимое. На свободных дорогах часть пассажиров едет на машине и такси, поэтому трамвай теряет ~1.5–2% посадок в ближайшие часы. В плотный вечерний трафик посадки на уровне нормы. Поправка `K_traffic(балл)` ∈ [0.98; 1.00] применяется к пиковым часам.
В прогнозе на ноябрь–декабрь фактических баллов нет, поэтому используется типичный балл для типа дня и часа (из истории 2025) с ручкой в UI. В проде — онлайн-балл из 4b.

**Ограничения:** баллы из канала покрывают около 40% дней (публикуются ситуативно, чаще в плохую погоду и в пиковые дни), значения даются по всему городу, а не по участкам трамвайных маршрутов.

## Ограничения
- Погода берётся одной точкой на весь город; у маршрутов на окраинах локальные осадки могут отличаться.
- Школьные каникулы у разных школ различаются (четверти или триместры); в данных эффект статистически незначим.
- Для 29–31.12 в истории нет прямого аналога (декабря 2024 нет в данных). Календарная поправка для 31.12 берётся по классу «праздник в будний день», а неделю перед Новым годом калибрует эксперт в UI.
