# Контекст проекта для Claude: хакатон Московского транспорта, «ИИ-прогноз загрузки трамвайных маршрутов»

Файл — передача контекста между сессиями и людьми. Сначала прочитай его, потом `README.md` (условия ТЗ), `ML_IDEAS.md` (идеи для ML) и `EXTERNAL_DATA.md` (внешние данные).

## Задача в двух словах
- Прогноз `boardings(route, date, hour)`: число успешных валидаций (`validation_result == 1`) на трамвайном маршруте за час.
- Маршруты: `1, 5, 7, 11, 12, 17, 25, 26, 28, 50`. История: 2025-01-01…2025-10-31 (train — янв–авг, test — сен–окт).
- Прогноз нужен на **2025-11-01…2025-12-31** (скрыт): 10 × 61 × 24 = 14 640 строк, файл `route;date;hour;prediction`, разделитель `;`.
- Метрика: `WAPE-score = max(0, 1 − Σ|y−ŷ|/Σy)`. Baseline ≈ 0.48, **10 баллов при > 0.88**.
- Дедлайн: **27.09.2026 23:59 МСК**. Лимит — 24 успешных сабмита в день, засчитывается лучший.
- Кроме ML нужен веб-сервис (Docker, API, карта, экспорт, коэффициенты в UI) — см. `README.md`.

## Ключевые решения (не пересматривать без причины)
1. **Внешние данные — только поправочные коэффициенты** к базовой модели на основном датасете. Target из внешних источников не брать (README датасета требует прогноз «на основе основного датасета»).
2. **Строго без утечки (объявление организаторов 25.09.2026):** решения перепроверят **в потоковом режиме** на ML-модели, а за «математический» скор (подгонку под лидерборд) критерий №1 обнуляют. Поэтому: модель видит только данные до отсечки; погода — архив прогнозов (`WEATHER_FOR_FORECAST="fcst"`) и только на `WEATHER_HORIZON_DAYS=7` дней вперёд, дальше K=1; LightGBM без погодных признаков; маршрут 5 — сценарий по аналогу из датасета (опубликованные числа поездок = внешний target, не берём), по умолчанию выключен. Разрешение организаторов на данные после 31.10 используем только для анализа, не в сабмите.
   Также от организаторов: лидерборд считается **по всему ноябрю–декабрю, скрытой части нет**; засчитывается **лучший** сабмит за все дни.
3. **Прогноз прямой (direct)**, без рекурсии по своим прогнозам. Организаторы в чате подтвердили: сразу вся сетка ноя–дек; «день/месяц» — уровни детализации; накопление ошибки на 61 день они оценивают как часть качества.
4. Валидация — только хронологическая, горизонт до 61 дня (фолды в ноутбуке: авг→сен–окт, сен→окт, мар→апр–май).

## Находки в данных (важно для прогноза)
- **Маршрута 5 нет в train/test** (0 посадок). По Telegram Дептранса его вернули только **17.12.2025** («Рижская» — Белорусский вокзал, 40 тыс. поездок за первую неделю). До 01.11 было известно лишь «к концу 2025». В baseline прогноз = 0; вариант — сценарий в UI.
- **Маршрут 50 с сентября ходит только по будням** (доля выходных упала с ~20% до ~1%). У **маршрута 7** с сентября выходные тоже просели (~11% против 19–22%).
- **Летом 2025 (≈13.07–13.08) закрыт участок Красносельская — Белорусский вокзал**: у маршрута 7 −37%, у маршрута 50 +31%. Эти дни нужно помечать как отдельный режим или исключать.
- **12.11.2025 запущен трамвайный диаметр Т1** (Метрогородок — «Университет»). Наших маршрутов в анонсе нет, но возможен переток пассажиров.
- Лето: −15–20% к уровню. Сен–окт — плато, это база для ноя–дек.
- Праздник по объёму ≈ воскресенье; праздник в будний день ≈ 0.45 от обычного будня.
- Простой профиль сен→окт даёт WAPE-score ≈ 0.90, поэтому baseline 0.48 почти ничего не значит.

## Текущий baseline (`baseline_colab.ipynb`)
- Профиль: `mean` за 4 «чистые» недели, типы дней `mon_thu / fri / sat / sun`; праздник → `sun`, рабочая суббота → будни × 0.85.
- Поправки: календарь, погода (OLS по будням, коэффициенты ограничены ±2%/ед.).
- LightGBM (L1) предсказывает отношение `y/profile`, ансамбль 50/50 с профилем.
- CV (среднее по 3 фолдам) ≈ **0.883**.
- Экспертные «ручки» без истории: `K_WORKING_SATURDAY=0.85`, `K_PRE_NEW_YEAR=0.92` (29–30.12), `K_SEASON={11: 1.0, 12: 0.98}`.

## Режимы маршрутов (26.09.2026, материалы воркшопа + Telegram Дептранса)
- Ремонт в Протопоповском пер.: с 06.09 по выходным 50 не ходит, 7 укорочен; **с 15.11 движение восстановлено** (t.me/DtOperativno/23565). В ноутбуке таблица `REGIMES`: вне интервала выходные 7/50 = текущий будний уровень × отношение выходные/будни до работ (7: 0.66/0.52, 50: 0.44/0.36).
- Эффект: +~190 тыс. посадок на выходных 15.11–31.12 против продления сен–окт; ожидаемо +1.5 п.п. WAPE. На CV не виден: ни один фолд не пересекает окончание работ.
- Маршрут 5 — ошибка выгрузки по словам организаторов, прогноз 0.

## Модель 2: ML (26.09.2026)
- Прямой многогоризонтный LightGBM: точки прогноза в истории каждые 7 дней (39 шт.), признаки только по данным до точки, цели на 1–61 день вперёд, без летних недель → ~570 тыс. примеров. Цель — факт/профиль с весом профиль (L1 = WAPE). Ансамбль с профилем, вес ML ≥ 0.3 (по CV).
- Прототип на 5 фолдах: профиль 0.8933, ML 0.8873, ансамбль 0.3 — 0.8942. ML сама по себе не лучше профиля (9 рядов, 10 мес., почасовой шум), но немного улучшает ансамбль и даёт честную ML-часть для потоковой проверки.
- Лидерборд: v1 0.885 → v2 без утечки 0.880 → + режимы 7/50 0.89.

## Потолок метрики (замер 25.09.2026 на labels)
- Профиль, подогнанный на самом октябре и проверенный на нём же (in-sample): WAPE-score 0.935–0.939. С точными суточными объёмами каждого маршрута: ~0.927 (вне выборки) / 0.948 (в выборке). Почасовой шум ограничивает скор, **0.95 недостижимо**; реалистичная цель на лидерборде — 0.89–0.91.
- v2 (`level_weeks=3` × форма суток за 12 недель, без фильтра аномалий): CV 0.8825 → 0.8886. Погода по дням на осенних фолдах эффекта не даёт.
- В ноутбуке есть тест на утечку (порча и обрезка данных после отсечки → прогноз бит в бит тот же) и потоковый бэктест (еженедельное переобучение, сен–окт ≈ 0.91). Генератор вариантов под лидерборд удалён.

## Как работать со скриптами
```bash
python external_data/build_external.py [--download]                      # календарь + погода + effects_report.csv
python external_data/parse_deptrans_tg.py all                            # события @DtRoad
python external_data/parse_deptrans_tg.py crawl --channel DtOperativno   # история баллов пробок
python external_data/parse_deptrans_tg.py extract --channel DtOperativno
python external_data/parse_deptrans_tg.py measure                        # effects_tg_report.csv
python external_data/yandex_traffic_collector.py loop --every 600        # онлайн-баллы Яндекса
```
Все скрипты запускаются из корня проекта. Нужны Python 3.10+, pandas, numpy; для ноутбука ещё lightgbm, tqdm, matplotlib.
