# README для Claude: внешние данные в проекте «ИИ-прогноз загрузки трамвайных маршрутов»

Прочитай этот файл целиком, прежде чем трогать внешние данные или ML-ноутбук.
Конституция проекта (требования организаторов, стек, архитектура) — `CLAUDE.md`. Если этот файл с ней расходится, приоритет у `CLAUDE.md`.
Подробные таблицы замеров лежат в `EXTERNAL_DATA.md`, прежний контекст — в `CLAUDE1.md`.

## 1. Зачем вообще нужны внешние данные

Причин три, все из ТЗ и уточнений организаторов:

1. **Баллы.** Критерий 2а даёт до **4 баллов**, по 1 за каждый внешний источник, если:
   - он **реально использован** в решении;
   - его **эффект измерен**;
   - есть **рабочая ссылка или способ получения**. Источник без ссылки не засчитывается.

   Категории: трафик · погода · календарь (праздники, каникулы) · прочее (события, перекрытия, ремонты).
2. **Качество прогноза.** История заканчивается 31.10.2025, а прогноз нужен на ноябрь–декабрь. В этом периоде есть события, которых модель по одной истории валидаций не видит:
   - перенос выходного на 03.11 и праздник 04.11;
   - рабочая суббота 01.11;
   - выходной 31.12;
   - погода (первый снег, морозы);
   - изменения трамвайной сети.
3. **Требование ТЗ к сервису:** прогноз учитывает погоду и календарь, а в UI есть корректирующие коэффициенты с немедленным пересчётом (+1 балл по 2в).

## 2. Главные правила применения (не нарушать)

- **Внешние данные — только поправочный множитель, а не база.**
  - Базовый прогноз строится **только на данных организаторов** (`dataset.zip`). Этого требует README датасета.
  - Внешний слой хранится отдельно и применяется на выдаче: `pred = base × K_calendar × K_weather × K_events × K_traffic`.
- **Источник недоступен → K = 1.** Сервис и модель работают и без внешних данных.
- **Target из внешних источников не брать.** Например, цифру «40 тыс. поездок на маршруте 5» из новости Дептранса в прогноз не подставляем.
- **Все K вычисляются ML-моделью, ручных коэффициентов нет.** Организаторы проверяют решение как ML-модель в потоковом режиме и аннулируют скор, полученный «математическим способом».
- **Данные после 31.10.2025 разрешены.** Организаторы 25.09.2026 разрешили, например, фактическую погоду и новости. Для прода лучше архив прогнозов погоды; в ноутбуке это переключатель `WEATHER_FOR_FORECAST`.

## 3. Источники: откуда и как получены

Все файлы лежат в `external_data/`, скрипты запускаются из корня проекта.

### 3.1 Календарь: праздники, переносы, сокращённые дни, школьные каникулы
- **Откуда:**
  - производственный календарь РФ — https://github.com/xmlcalendar/data, файл [`ru/2025/calendar.xml`](https://raw.githubusercontent.com/xmlcalendar/data/master/ru/2025/calendar.xml); сверено с [КонсультантПлюс](https://www.consultant.ru/law/ref/calendar/proizvodstvennye/2025/);
  - школьные каникулы Москвы — [banki.ru](https://www.banki.ru/wikibank/shkolnye_kanikuly_2025_2026/) и [РБК](https://www.rbc.ru/life/news/650956c49a7947086a7f6d64).
- **Как получено:** `python external_data/build_external.py --download` скачивает XML и собирает `calendar_2025.csv`.
- **Поля:** `is_holiday, is_short_workday, is_working_weekend, is_day_off, day_type, school_holiday, days_to_new_year, ...`
- **Зачем:** праздник в будний день даёт ~0.45 от обычного будня, по объёму он ≈ воскресенье. Без календаря модель спрогнозирует 03–04.11 и 31.12 как будни и сильно промахнётся.
- **Нюанс:** в ML-модели **не используем** `school_holiday` и `days_to_new_year`.
  - Каникулы в обучении почти всегда совпадают с летом, и модель путает их с сезонным спадом. Проверено экспериментом: они портили октябрь.
  - Примеров «дней до НГ» в обучении нет.

### 3.2 Погода
- **Откуда:** Open-Meteo, бесплатно, без ключа, CC BY 4.0:
  - факт (реанализ ERA5 / IFS): https://open-meteo.com/en/docs/historical-weather-api;
  - архив прогнозов: https://open-meteo.com/en/docs/historical-forecast-api.
- **Точка и период:** центр Москвы 55.7558, 37.6173; почасово; 01.01–31.12.2025.
- **Как получено:** тот же `build_external.py --download`. Результат — `weather_fact_hourly_2025.csv`, `weather_fcst_hourly_2025.csv`.
- **Зачем:** осадки уменьшают посадки, тепло увеличивает. Эффект ~1% на одно стандартное отклонение, но устойчивый по знаку.
- **Нюанс:** в ML используем не абсолютную температуру, а **аномалию** — отклонение от среднего за 28 предыдущих дней. Абсолютная температура кодирует сезон, и модель начинает выучивать «лето = спад». В модели заданы монотонные ограничения: теплее → посадок не меньше, осадки → не больше.

### 3.3 События, перекрытия, изменения трамвайной сети
- **Откуда:** официальный Telegram-канал Департамента транспорта Москвы — https://t.me/s/DtRoad (публичная веб-версия, без авторизации).
- **Как получено:** собственный парсер `external_data/parse_deptrans_tg.py`:
  - `crawl` — листает `?before=<id>` и собирает 4 646 постов за 2025 год;
  - `extract` — регулярками размечает категории (`closure, tram_works, tram_route_change, mass_event, weather_alert, new_line`), номера наших маршрутов и даты из текста.

  Результат — `deptrans_posts_raw.jsonl`, `events_2025.csv`.
- **Зачем:** события объясняют аномалии, которые модель иначе примет за шум:
  - **13.07–13.08.2025** закрыт участок Красносельская — Белорусский вокзал: у маршрута 7 −37%, у маршрута 50 +31%;
  - **12.11.2025** запущен трамвайный диаметр Т1, возможен переток пассажиров;
  - **17.12.2025** вернули маршрут 5 — поэтому его нет в train/test.
- **Нюанс:** общегородские перекрытия и массовые мероприятия на трамвай почти не влияют. Работает признак «работы/перекрытия с упоминанием конкретного маршрута».

### 3.4 Трафик (баллы пробок)
- **Откуда:**
  - история — Telegram «Дептранс. Оперативно»: https://t.me/s/DtOperativno. Там ЦОДД публикует баллы: «по данным ЦОДД, вечером до 7 баллов»;
  - онлайн — публичный XML Яндекса https://export.yandex.ru/bar/reginfo.xml?region=213: текущий балл 0–10 по Москве, без ключа.
- **Как получено:**
  - история: `parse_deptrans_tg.py crawl --channel DtOperativno` → `extract --channel DtOperativno` → `DtOperativno_traffic_scores_2025.csv`, 344 значения за 150 дней;
  - онлайн: `yandex_traffic_collector.py loop --every 600` → `yandex_traffic_live.csv`.
- **Почему не готовый архив:** открытого архива пробок нет. TomTom недоступен, архив smotra.ru закрыт в 2010 году, снимков в Wayback нет.
- **Зачем:** в часы со свободными дорогами трамвай теряет ~1.5–2% посадок, потому что люди едут на машине. Эффект слабый, но измеренный.
- **Ограничение:** баллы покрывают ~40% дней, значение одно на весь город.

## 4. Как это встроено в ML (`ml_streaming_colab.ipynb`, исходник `tools/build_nb_ml.py`)

```
Модель A (LightGBM, ТОЛЬКО данные организаторов): лаговые признаки → base
Модель B (LightGBM, внешний слой): учит y / base по календарю, погоде, событиям, трафику
K_g = B(источники ≤ g реальные) / B(источники < g реальные), остальные — нейтральные («источник недоступен»)
pred = base × K_calendar × K_weather × K_events × K_traffic      ← хранить компоненты отдельно, UI может менять K
```
- B обучается на **кросс-фит** прогнозах A, чтобы видеть честные ошибки базы.
- **Источник попадает в финальную модель, только если его вклад на валидации > 0.** Это выбор по данным, а не руками.
- Артефакты:
  - `contract.json` — признаки, нейтральные значения, выбранные источники, метрики;
  - `forecast_components.csv` — `base` и все `K_*` по строкам для загрузки в БД;
  - модели `.txt` и `.onnx`.

## 5. Измеренный эффект (ablation в ML-ноутбуке; среднее по 3 хронологическим фолдам, WAPE-score)

| Вариант | WAPE-score | Вклад источника |
|---|---:|---:|
| A (без внешних) | 0.8179 | — |
| A×B (все источники) | 0.8202 | — |
| без календаря | 0.8155 | **+0.47 п.п.** |
| без погоды | 0.8186 | +0.16 п.п. |
| без событий | 0.8120 | **+0.82 п.п.** |
| без трафика | 0.8197 | +0.05 п.п. |

Фолды: F1 — авг → сен–окт; F2 — сен → окт; F4 — июнь → июнь–авг (с праздниками 12–13.06).

**Открытая проблема:** на F2 (сен → окт, ближайший аналог ноября) слой B ухудшает результат, 0.9025 → 0.8828. В среднем он помогает за счёт летних фолдов. Следующий шаг — найти, какой источник вредит в октябре, и выбирать источники так, чтобы вклад был > 0 **на каждом фолде** или хотя бы на F2.
