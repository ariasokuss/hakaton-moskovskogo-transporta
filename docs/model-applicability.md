# Область определения и адаптации модели (критерий 2б)

Модель: ансамбль **профиля** (уровень маршрута × форма суток × календарь × режимы × погода × сбои) и **LightGBM**
(прямой многогоризонтный, обучен на ~90 «точках прогноза» истории). Ноутбук — `mostrans_handoff/mostrans/baseline_colab.ipynb`,
исходник — `tools/build_nb.py`. Все цифры ниже — из прогона ноутбука.

## 1. Где модель валидна (область определения)

| Измерение | Валидно | Чем подтверждено |
|---|---|---|
| Маршруты | 9 маршрутов с историей: 1, 7, 11, 12, 17, 25, 26, 28, 50 | фолды F1–F5, потоковый бэктест |
| Маршрут 5 | **вне области**: в истории 0 посадок (ошибка выгрузки по словам организаторов) → прогноз 0; сценарий запуска по маршруту-аналогу — только как ручка | — |
| Горизонт | 1–61 день вперёд, прямой прогноз без рекурсии; ошибка не растёт с горизонтом | фолды на 19–61 день: 0.85–0.91; поток 1 день ≈ 0.910, 7 дней ≈ 0.911; лидерборд (61 день) 0.890 |
| Детализация | маршрут × дата × час; день / месяц — сумма часов | метрика ТЗ считается на этом уровне |
| История для обучения | уровень — последние 3 «чистые» недели, форма суток — 16 недель; ML — точки прогноза с февраля | подбор по CV |
| Режим эксплуатации | обычная работа + **известные** режимы (ремонты, отмены по выходным), заданные в таблице `REGIMES` | ремонт 7/50: лидерборд 0.880 → 0.890 |
| Календарь | выходные, праздники, переносы, сокращённые дни, рабочие субботы, каникулы | фолд с майскими праздниками: +3.7 п.п. |

Точность по маршрутам неравномерна: крупные 17, 12, 11, 1, 26 — WAPE-score 0.90–0.93; малые 25, 28 и режимные 7, 50 — 0.76–0.86.

## 2. Где точность ниже (пределы применимости)

- **Новогодняя неделя (29–31.12)**: декабря в истории нет. Коэффициенты `K_PRE_NEW_YEAR`, `K_SEASON[12]` экспертные — ручки в UI.
- **Необъявленные смены режима** (внезапные ремонты, отмены): модель узнаёт о них только из таблицы режимов; до этого ошибка по маршруту 30–100%.
- **Сбои в реальном времени** (ДТП, контактная сеть): заранее неизвестны; при появлении поста модель снижает прогноз маршрута
  на 3 часа (`K_incident ≈ 0.84`), но только если пост уже получен.
- **Экстремальная погода** дальше 7 дней: прогноз погоды на такой горизонт не используется (K = 1).
- **Ночные часы** 0–4: малые объёмы, относительная ошибка высокая, на WAPE почти не влияют.
- **Остановки**: в валидациях нет остановки (`place_id` — депо). Остановочная детализация — распределение прогноза маршрута
  по остановкам через справочник (только маршруты 1, 5, 7, 11, 12 есть в справочнике), это оценка, а не наблюдение.
- **Уникальные пассажиры**: `crd_hashcode` не идентификатор человека (токенизация), метрику не строим.
- Горизонт **год** — качественный сценарий (сезонный индекс 2025 года ± 2σ по маршрутам), не точечный прогноз.

## 3. От каких внешних данных зависит

| Данные | Обязательность | Если нет |
|---|---|---|
| Производственный календарь (xmlcalendar) | **обязателен** | праздники прогнозируются как обычные дни, ошибка на праздниках ×2–3 |
| Таблица режимов (Telegram Дептранса, новости) | **обязательна** при известных работах | модель продолжает последний режим (как было до исправления 7/50) |
| Прогноз погоды (Open-Meteo) | желателен, горизонт ≤ 7 дней | K = 1; потеря до 1–3 п.п. летом в дождливые дни (на день вперёд), в холодный сезон ≈ 0 |
| Посты о сбоях (@DtOperativno) | желательны для оперативного пересчёта | K = 1 |
| Трафик (баллы ЦОДД, Яндекс) | не используется в прогнозе (эффект не подтверждён) | — ; в UI ручка |

Отказоустойчивость: любой внешний источник недоступен → его коэффициент = 1, работает базовый прогноз на данных организаторов.

## 4. Как переносить (область адаптации)

**На новый период** (потоковый режим): ежедневное/еженедельное переобучение на данных «до сегодня» — ячейка потокового бэктеста
показывает именно этот режим. Новые праздники — из календаря следующего года (`xmlcalendar_ru_2026.xml` уже лежит).

**На новый маршрут**:
1. первые 3 недели — **аналог**: форма суток от маршрута-кластера (центр/периферия, похожий суточный профиль),
   уровень — из провозной способности (число выходов × вместимость из листа «Наряд») или по маршруту-аналогу (`ROUTE5_ANALOG_ROUTE`);
2. после 3 недель валидаций — собственный уровень, после 8–16 недель — собственная форма суток;
3. LightGBM глобальный: новый маршрут добавляется категорией и дообучается на общих точках прогноза.

**На другой вид транспорта / город**: код не привязан к трамваю, кроме справочников и таблицы режимов; нужен тот же вход
`route × date × hour`, производственный календарь и источник новостей о работах.

## 5. Как контролировать деградацию

- потоковый бэктест (горизонт 1 и 7 дней) после каждого переобучения; порог — падение WAPE-score > 2 п.п. к медиане последних 4 недель;
- тест на утечку (порча данных после отсечки) обязателен при изменении признаков;
- аномалии маршрута (±40% к медиане того же дня недели за 4 прошлые недели) — сигнал проверить новости и добавить режим.
