# ML-контур «Пантограф»

Прогноз `boardings(route, date, hour)` — посадок на трамвайных маршрутах по часам на 01.11–31.12.2025.
Итог: **WAPE-score 0.89731** на лидерборде (порог максимального балла — 0.88).

## Состав каталога

```
ml/
├── pantograph_best_colab.ipynb   ← финальный ноутбук: данные → профиль → LightGBM → поправки → сабмит и артефакты

## Как устроен прогноз

```
профиль (форма суток 16 нед. × уровень 3 нед., медиана)  ─┐
LightGBM: 3 горизонта обучения × 3 seed (9 моделей)       ─┼─► смесь по горизонту (вес ML 0.6 на днях 1–21, 0.2 дальше)
                                                           │
× календарь (праздники, рабочая суббота)   × погода (дождь в тепло, первые 7 дней)
× режимы маршрутов (ремонт 7/50 по выходным до 14.11)      × сбои на маршруте
× сезонный рост уровня SEASON_GROWTH = 1.03 (будни сен→окт +3.4%)          → маршрут 5 = 0
```

Подробно:

```
профиль (модель 1)   = уровень маршрута (медиана 3 недель) × форма суток (0.7 · 16 недель + 0.3 · последние 4 недели)
                       × календарь (праздник — к воскресеньям той же поры) × режимы маршрутов × погода (≤ 7 дней) × сбои
LightGBM (модель 2)  = 9 бустеров: 3 горизонта обучения (цели на 1–3, 1–14, 1–28 дней) × 3 seed, ~90 точек прогноза истории;
                       цель — факт / профиль, вес — профиль (L1 ⇒ WAPE); 15 листьев, ≥ 1000 примеров в листе (сильная регуляризация);
                       признаки: календарь, лаги того же часа, тренд уровня, режим, доля часа в суточном профиле
итог                 = (1 − w(h)) · профиль + w(h) · ML,   w(h) = 0.6 для дней ≤ 21, 0.2 дальше (подбор по CV)
                       × сезонный рост уровня SEASON_GROWTH;   маршрут 5 = 0
```

Прогноз **прямой** (direct) на весь горизонт 61 день: признаки фиксируются в точке прогноза, рекурсии нет.
Валидация — хронологические фолды (6 шт.), только прошлые данные; в ноутбуке есть тест на утечку,
потоковый бэктест (переобучение каждую неделю) и ячейка **проверки гипотез** — гипотеза попадает в модель,
только если улучшает средний WAPE-score фолдов.

## Запуск

### Google Colab (основной способ, CPU достаточно, ~25–35 мин)

1. Откройте `ml/pantograph_best_colab.ipynb` в Colab → **Runtime → Run all**, разрешите доступ к Drive.
2. Датасет организаторов скачивается сам с публичного Kaggle `shotme/moscow-transport` (ключ не нужен).
3. Внешние данные берутся из `MyDrive/mostrans/external_data/`; если папки нет — ноутбук найдёт её на Drive
   или скачает из этого репозитория (`EXT_REPO_URL`, `EXT_REPO_BRANCH` в первой ячейке).
4. Результат: `MyDrive/mostrans/submissions/submission_ml_<время>.csv` и `service_artifacts.zip` для сервиса.

См. [`../LOCAL_SETUP.md`](../LOCAL_SETUP.md), раздел «ML локально».

```

## Основные параметры (первая ячейка ноутбука)

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `SEASON_GROWTH` | `1.03` | сезонный рост уровня к зиме, множитель итогового прогноза |
| `WEATHER_FOR_FORECAST` | `fcst` | погода на горизонте — архив прогнозов Open-Meteo (то, что известно заранее) |
| `WEATHER_HORIZON_DAYS` | `7` | погода учитывается только на первые 7 дней горизонта |
| `EVENTS_MODE` | `all` | режимы маршрутов по всем опубликованным новостям (данные после 31.10 разрешены организаторами) |
| `TRAFFIC_IN_MODEL` | `False` | баллы пробок: эффект измерен, прогноз не улучшает — в сабмит не входят |
| `ROUTE5_ENABLED` | `False` | маршрут 5 — нули (указание организаторов) |
| `KAGGLE_FULL_DOWNLOAD` | `False` | `True` — скачать сырые CSV (~10 ГБ) и прогнать пайплайн приёма со сверкой |
| `USE_CHECKPOINTS` | `True` | долгие шаги кэшируются на Drive; изменили код/данные — шаг пересчитается |
| `ORIGIN_STEP_DAYS` | `3` | шаг «точек прогноза» в истории для обучения LightGBM |
| `BLEND_GRID` | `w_near × w_far × h_cut` | сетка веса ML по горизонту, выбор по CV |
| `ML_ANCHOR_LEVEL` | `True` | суммарный уровень маршрута на горизонте — от профиля, распределение по дням и часам — от ML |
| `K_PRE_NEW_YEAR` | `None` | 29–30.12: `None` — по аналогу первых рабочих дней января 2025 (≈ 0.90) |
| `K_WORKING_SATURDAY` | `0.85` | рабочая суббота 01.11: будний профиль × K |

## Проверки внутри ноутбука

- **Тест на утечку**: данные после отсечки портятся или обрезаются — прогноз обязан совпасть бит в бит.
- **Потоковый бэктест**: сентябрь–октябрь, еженедельное переобучение, горизонт 7 дней.
- **Эффект внешних источников** (критерий 2а): потоковый прогноз на день вперёд с отключением источников по одному; погода — отдельно на феврале–октябре.
- **Проверка гипотез**: ансамбль окон формы суток, рост уровня по тренду — включаются, только если улучшают CV.
- **6 хронологических фолдов** (горизонт 19–61 день), включая фолд с майскими праздниками и зимний.

## Чекпоинты (повторный запуск без переобучения)

Папка `MyDrive/mostrans/checkpoints/` (локально — `ml/checkpoints/`):

| Что | Файл |
|---|---|
| подбор параметров профиля | `profile_grid_<ключ>.pkl` |
| прогноз на день вперёд для оценки погоды | `day_ahead_resid_<ключ>.pkl` |
| точки прогноза (признаки ~1.3 млн примеров) | `origin_frames_<ключ>.pkl` |
| замер эффекта внешних источников | `stream_1d_<ключ>.pkl` |
| веса каждой модели LightGBM (фолды, потоковый бэктест, финал) | `lgbm/lgbm_<ключ>.txt` |

Ключ — хеш кода ноутбука, данных и настроек (для моделей — хеш обучающей выборки, seed, параметров и версии LightGBM).
Изменили код, данные или параметр — нужный шаг пересчитается сам. Повторный **Run all** с теми же настройками идёт
в разы быстрее; `USE_CHECKPOINTS = False` — всё с нуля. Тест на утечку всегда пересчитывает признаки заново.
